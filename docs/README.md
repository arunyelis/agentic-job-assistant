# Product documentation

This directory is the product memory for Career Workspace. It records why the product exists, what we decided, and how the system is expected to evolve.

## Working agreement

- Update `product/vision.md` when the audience, problem, or product principles change.
- Update `product/roadmap.md` when release priorities change.
- Update `product/design-system.md` before introducing a new visual pattern or component family.
- Update the architecture documents when data flow, trust boundaries, or infrastructure change.
- Add a dated record under `decisions/` for a decision that would be expensive to reverse.
- Add research observations to `product/research-journal.md` without rewriting the original observation.

The documents should explain decisions in plain language. They are not marketing material and should not claim that a feature or safeguard exists before it is implemented.
